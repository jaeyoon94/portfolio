빌드 및 업데이트 관리

업데이트 범위와 일정을 맞추고, 빌드 정보가 QA와 사업부에 전달되도록 관리했습니다.
빌드 전 이슈 점검부터 점검 준비와 라이브 대응까지 확인했습니다.

실제 수행 · UNDECEMBER

빌드 노트 템플릿 개선을 비롯해 빌드 전 이슈 완료 여부 점검, 빌드 노트 작성·공유, QA·사업부 대상 빌드 정보 전달을 담당했습니다.
정기·비정기 점검과 라이브 이슈 대응도 함께 관리했습니다.

빌드 노트와 운영 업무 사례 보기

기술 환경은 개발팀 담당빌드 서버와 CI/CD, Jenkins·Horde·BuildGraph, Perforce 운영 및 브랜치 정책은 개발팀이 구축·운영했습니다.
제 역할은 일정·범위·이슈 조율과 업데이트 준비 관리였습니다.

QA · 결과 공유 예정

실제로 확인된 경험은 QA·사업부에 빌드 정보를 전달하고 확인한 업무입니다.
위 보드 운영이나 빌드 번호 관리 방식까지 수행했다고 주장하지 않습니다.

결함이 나오면 일정과 범위를 다시 확인

일반 프로세스 예시 · 실제 프로젝트의 의사결정 규칙은 자료에 없습니다.

  1. 결함 접수대상 빌드·재현 조건·영향 확인
  2. 개발·QA와 영향 검토진행 불가·서비스 영향·검증 소요 확인
    • 배포 차단 필요 → 보류·수정 범위 협의
    • 영향 제한적 → 포함·제외·후속 수정안 협의
  3. 수정·재빌드가 필요하면개발팀 수정·재빌드 → QA 재검증
    PM은 담당자·전달일·배포 영향 조율
  4. 검증 결과로 다시 판단미해결이면 재검토, 충족하면 릴리즈 준비
    배포 여부는 조직의 승인 절차에 따라 결정

릴리즈 준비 체크리스트

일반 점검 항목 예시 · 실제 릴리즈의 완료 상태를 표시한 목록이 아닙니다.

  • 일정·반영 범위대상 기능·제외 항목·마감 변경 공유
  • 빌드 정보대상 버전·변경 목록·알려진 이슈 확인
  • QA 검증 결과차단 결함·잔여 이슈·재검증 여부 확인
  • 점검·공지 준비점검 시나리오·공지 담당자·준비 상태 확인
  • 배포 판단·비상 대응승인 담당자·연락 체계·복구 방안 확인
  • 업데이트 이후모니터링 담당·라이브 이슈 후속 일정 공유

배포 실행·기술 복구는 개발 담당 조직이 수행하며, PM의 단독 배포 승인이나 롤백 수행 경험을 의미하지 않습니다.

경험과 예시의 구분 · 근거 자료

UNDECEMBER: 경력기술서 1~2쪽의 업데이트·빌드 및 라이브 서비스 관리, 협업 프로세스 개선 항목과 포트폴리오 10쪽의 빌드 노트 템플릿 개선을 근거로 작성했습니다.
실제 사용한 빌드 노트 원본이나 QA 상태 보드는 제공 자료에서 확인하지 못했습니다.

다른 프로젝트의 빌드 관리 사례는 이 섹션에서 확장하지 않았습니다.
책임 분담 표, QA 전달 보드, 결함 분기와 릴리즈 체크리스트는 업무 이해를 위한 일반 예시이며, 개인의 실제 수행 기록과 구분합니다.
