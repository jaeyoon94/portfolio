개발 PM 업무

프로토타입 개발이 끝난 뒤 합류해 풀 프로덕션과 심사 빌드 준비에 참여했습니다. 기획·아트·기술 작업이 맞물려 있어, 스펙이 바뀌면 일정과 리소스를 함께 확인했습니다.

Asana와 WBS로 개발 일정과 태스크를 확인했습니다. 리소스 현황판과 외주 발주 리스트로 제작 상황을 살폈고, 외부 협력사의 변경 요청은 기록한 뒤 일정을 협의했습니다.

운영한 회의

개발·아트·사업 회의의 결정 사항을 모았습니다.

후속 작업의 공백

회의에서 결정한 내용을 후속 업무로 옮길 때, 담당자와 완료 기한을 함께 확인하기 어려운 구간이 있었습니다. 누가 언제까지 처리할지 다시 확인해야 했습니다.

  1. Meeting논의
  2. Decision결정 사항
  3. 다시 확인담당자와 완료 기한
  4. Execution실행

담당자·기한 연결

담당자와 기한을 회의 결과에 함께 남겨야 한다고 봤습니다.

  1. Decision결정 사항 확인
  2. Issue실행할 일로 정리
  3. Owner담당자 지정
  4. Deadline완료 기한 확인

할 일마다 담당자와 완료 기한을 함께 기록했습니다. 회의가 끝난 뒤에는 해당 항목을 보며 진행 상황과 변경 사항을 확인했습니다.

종결 아이템 수가 적다
아이템 수와 직업군별 활용 범위

공지된 종결 아이템은 5종이었습니다. 여러 직업군에서 활용할 선택지가 충분한지 검토할 항목으로 정리했습니다.

기존 아이템 너프에 대한 우려
예정된 조정이 플레이에 미칠 영향

스탯 조정 이후 예상되는 이슈를 검토할 수 있도록 플레이 맥락과 관련 자료를 준비했습니다.

판매 상품의 실용성이 낮다
상품 구성과 실제 활용성

판매 항목의 수와 구성에서 어떤 부분을 다시 검토할지 정리해 사업 조직과 논의했습니다.

검토와 변경 방향

반응을 그대로 요구사항으로 옮기지는 않았습니다.

아이템 구성, 밸런스, 판매 상품으로 쟁점을 나누고 변경 영향을 검토했습니다. PM은 반응과 근거를 정리해 논의를 지원했고, 변경 방향은 개발·사업 조직의 협의를 거쳤습니다.

  1. Signal공지 이후 반응 확인
  2. Review영향·변경 범위 검토
  3. Decision개발·사업 논의
  4. Revision업데이트 내용 조정
  5. Live Update빌드·서비스 반영

라이브 반영

변경 내용을 작업·빌드·업데이트로 연결

작업 범위와 일정
변경된 업데이트 스펙을 기준으로 작업 범위와 개발 일정을 조율하고, WBS와 담당자를 확인했습니다.
빌드와 잔여 이슈
빌드별 변경 내용과 잔여 이슈를 확인하며 최종 폴리싱과 업데이트 준비를 관리했습니다.
점검과 라이브 대응
점검 회의에서 준비 상태를 확인하고, 업데이트 이후에는 라이브 이슈를 일일 단위로 갱신했습니다.
별도 확인: 원자료에 기록된 업데이트 이후 지표

기존 포트폴리오에는 시즌 9 대비 시즌 10의 DAU 약 2배, 매출 약 1.5배가 기록되어 있습니다.

서비스 전체의 결과이며, 이 페이지의 개별 변경이나 PM 개인의 효과로 분리한 수치는 아닙니다. 비교 집계 기간은 원자료에 명시되어 있지 않습니다.

업데이트 운영을 뒷받침한 업무

이슈·일정·빌드 정보를 확인하는 방식

Jira · Asana
Jira를 신규 도입하고 이슈 상태·심각도·처리 흐름을 정리했습니다. Asana에서는 빌드별 스펙과 담당 업무, 우선순위와 잔여 이슈를 확인할 수 있도록 일정을 구성했습니다.
빌드 노트
빌드 노트의 템플릿을 정비하고 작성 작업을 자동화했습니다.
정례·점검 회의
부서 간 작업과 연관된 이슈를 정례 회의에서 확인하고, 점검 회의에서 업데이트 준비 상태를 함께 확인했습니다.

Live Service PM 관점

계획 이후에 들어온 신호도 검토해야 했습니다.

정책 초안은 자진신고를 자동 면책이나 자동 복귀로 보지 않았습니다. 신고된 사실과 제출 자료를 검증한 뒤 제한적으로 감면을 검토하는 방식입니다.

  2. 협의

    유관부서와 추진 방향 검토

    협의한 방향을 추진할 기반 마련

문서에 기록된 run.bat·Python 실행 파일을 통해 관리 정보를 동기화하는 흐름입니다. 모든 도구가 실시간 양방향으로 연동되는 구조로 설명하지 않습니다.

자동 실행 후에는 반영 결과를 확인하고, 예외가 있으면 처리 기준과 요구사항을 수정해 다시 실행했습니다. 공정률 산식이나 가중치는 확인되지 않아 표시하지 않습니다.

Excel Copy Tool

반복 번역 작업을 규칙과 예외 처리로 개선

TextKey를 기준으로 번역 데이터를 대조하고, 동일한 키가 존재하는 모든 대상 행에 반영하도록 처리 범위를 확장했습니다. 한국어 원문 변경 여부를 확인하고, 원문이 달라진 항목은 기존 번역을 보호하도록 예외 처리를 정리했습니다.

파일 준비 → TextKey 매칭 → 한국어 원문 완전 일치 여부 확인. 일치하면 번역 빈칸을 보완하고 다중 언어 열에 반영하며, 불일치하면 적용을 생략하고 ‘재수정’으로 구분합니다. 결과는 사용자가 Excel에서 확인한 뒤 최종 저장합니다.

주요 판단 기준을 설명하는 개념도입니다. 실제 소스의 함수 호출 순서나 전체 예외 처리를 재현한 순서도는 아닙니다.

처리 규칙을 바꾼 요구사항

중복 키 처리
첫 번째 일치 항목만 처리하는 방식에서, 키가 일치하는 모든 대상 행을 처리하도록 요구사항을 개선했습니다.
원문 변경 보호
한국어 원문이 달라진 항목은 번역 적용을 생략하고 ‘재수정’으로 구분해 수동 검토 대상으로 남겼습니다.
처리 범위 확장
단일 열 복사에서 O–AG의 19개 언어 열을 반영하는 다중 열 처리로 확장했습니다. 반복된 한국어의 번역 빈칸은 완전히 일치하는 원문을 기준으로 보완하도록 설계했습니다.

AI와 처리 로직을 구현·수정하고, 업무 데이터에서 발견한 예외를 다음 요구사항으로 정리했습니다. 승인된 업무 환경의 파일 처리 제약 안에서 사용자가 결과를 확인하고 최종 저장하도록 했습니다.

기존 업무 기록

검증과 요구사항 개선

아래는 실제 포트폴리오에 기록된 구현·검증·수정 과정입니다. 실행 화면이나 코드 캡처가 아닌, 당시 업무 과정을 정리한 문서입니다.

소스·GUI·패키징 확인 범위

현재 저장소에서는 ProjectDME_클로드의 소스·README·config.json·Git 이력과 Excel Copy Tool의 Python 소스·GUI·패키징 파일을 확인하지 못했습니다.

GUI와 실행 파일 배포, 인증·경로 설정, Commit 절차는 검증된 구현 단계로 표시하지 않았습니다. 실제 소스와 실행 자료 확인 후 보완할 항목입니다.

한가위 페스타
참여에서 컬렉션 완성까지

이벤트에 참여하며 컬렉션의 가치를 먼저 경험하고, 더 수집하고 싶은 사용자가 구매를 선택하는 흐름을 제안합니다.

무료 경험 뒤에 놓는 구매 선택

  1. 이벤트 참여한가위 페스타 진입
  2. 무료 경험컬렉션 가치 경험
  3. 수집 관심완성하고 싶은 이유
  4. 선택적 구매컬렉션 확장
  5. 완성과 보상한정 보상으로 연결

기획 제안의 사용자 여정입니다. 실제 이용 행동이나 출시 상품을 뜻하지 않습니다.

구매 전에 경험을 제공합니다.

상품만 먼저 제시하는 대신 이벤트 참여와 수집 경험을 연결합니다. 상품 구성과 보상 가치, 상품 간 역할 차이는 컬렉션 완성이라는 목적에 맞춰 검토합니다.

구체적인 상품 구성·가격 가설·검증 지표는 상세 기획 원자료 확인 후 제시합니다.

포트폴리오 기획 제안 · Artale

핵심 플레이를 남기고,
확장할 영역을 검토합니다.

클래식 MMORPG의 성장·파밍·거래·커뮤니티 경험을 기준으로, 어디까지 유료 선택지를 둘 수 있는지 살펴보는 BM 분석·기획 사례입니다.

기존 경험과 제안의 경계

먼저 확인할 기존 BM

펫·편의·거래·외형 상품이 이미 제공하는 가치와 이용 흐름을 확인합니다. 기존 기능으로 해결되는 영역을 새로운 불편으로 정의하지 않습니다.

검토 항목이며 현재 서비스의 상품 목록을 확정해 제시한 것은 아닙니다.

기획 기준

성장과 파밍의 핵심 경험은 남깁니다. 직접적인 전투력 판매보다 사용자가 선택할 수 있는 편의·경험 확장 범위를 검토합니다.

확장 방향

기존 상품과 중복되지 않는 편의·거래·패스의 가능성을 검토합니다. 사용할 상황과 얻는 가치가 설명되는 범위에서 상품과 구매 후 이용 흐름을 구체화합니다.

성장·파밍 경험을 기준으로 유료화 범위를 검토하는 제안입니다. 세부 상품과 가격, 성과 수치는 제시하지 않습니다.

맡길 작업과 검토 기준부터 정합니다.

규칙을 설명하고 결과를 확인할 수 있는 업무에 AI를 적용합니다. 목적과 처리 기준은 PM이 정하고, 검토한 결과를 업무에 반영합니다.
