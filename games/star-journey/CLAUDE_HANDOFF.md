## 사용자 목표와 중요한 맥락

웹 기반 게임 개발사 경영 시뮬레이션이다. 직원 입사 또는 공동 창업으로 시작하고, 직군별 업무·협업·경영 의사결정으로 게임을 만든다. 현재 플레이는 첫 공개 데모 제작 중심이다. 프로토타입부터 데모, 출시, 라이브 서비스까지 장기적으로 확장하려는 기획이며, 이 전체 단계가 모두 구현된 것은 아니다.

디자인은 ZEP 같은 가상 오피스와 큰 머리·작은 몸의 한국형 도트 캐릭터를 참고했다. 사용자는 잘린 오피스 이미지를 배경으로 붙이거나 코인 수집 게임으로 바꾸는 방향을 원하지 않는다. 사무실은 실제로 걸어 다니고 상호작용하는 공간이어야 한다.

**가장 시급한 이슈는 자연스러운 걷기 모션이다.** 사용자는 이동 중 캐릭터 이미지가 깨지는 문제를 여러 번 지적했다. 이미지 하단을 잘라 다리처럼 흔들거나, 여러 띠로 나눠 변형하는 수정은 실패했다. v13에서 전신 정지 이미지와 작은 흔들림만 남겼더니, 사용자는 걷기 모션을 없앤 것에 강하게 불만을 표시했다. 따라서 **실제 발·팔 자세가 다른 전신 걷기 프레임**으로 해결해야 한다. 모션 제거를 해결로 제시하지 말 것.

## 실행 방법

Node.js가 있으면 외부 패키지 설치 없이 실행할 수 있다.

```text
cd current-work
node serve.cjs
```

브라우저에서 `http://127.0.0.1:4318/`을 연다. `dist/index.html`을 직접 파일로 열기보다 로컬 서버를 사용한다. 서버 종료는 Ctrl+C.

프레임워크·번들러·package.json이 없는 정적 HTML/CSS/JS 프로젝트다. `.openai/hosting.json`의 정적 배포 폴더는 `dist`다.

## 새 걷기 작업: 구현된 부분과 남은 일

현재 작업 파일은 기존 정지/착석 아틀라스를 유지하면서, 이동 중에는 별도의 걷기 아틀라스에서 **완전한 전신 포즈 하나**를 골라 그린다. 플레이어와 NPC에 같은 렌더러를 사용한다. 몸을 잘라 흔드는 방식이 아니다.

새 아틀라스는 imagegen으로 생성된 RGBA PNG, 실제 해상도 **887×1774**다. 프롬프트에서 요구한 크기와 실제 출력 크기가 달랐으므로 256 고정 셀로 해석하면 안 된다. 6열×8행이며, 열은 기존 6종 캐릭터 순서다. 행은 아래 순서다.

1. 정면 왼발 자세
2. 정면 오른발 자세
3. 후면 왼발 자세
4. 후면 오른발 자세
5. 왼쪽 측면 자세 A
6. 왼쪽 측면 자세 B
7. 오른쪽 측면 자세 A
8. 오른쪽 측면 자세 B

`analyze-walk.py`가 셀 경계와 알파 bounding box를 읽어, 기존 정지 이미지와 표시 크기·발 기준점을 맞춘 `walk-atlas.js`를 생성했다. `sprite()`는 이동 시 `WalkingAtlas.frames[direction*2+pose][character]`를 선택한다. 정지·착석은 기존 이미지로 돌아간다. 새 스크립트 URL에는 `?v=14` 캐시 구분자가 추가되어 있다. 이것은 **배포 버전 번호 확정이 아니다**.

아직 해야 할 일:

1. 브라우저에서 6종·4방향의 정지→걷기→정지, 방향 전환, NPC 배회를 **실제 재생으로 확인**한다. 이미지 생성물의 발 자세 차이와 정지/이동 간 크기·머리 위치가 충분히 자연스러운지 판단한다.
2. 2포즈 교대의 속도·보폭이 거칠면 전신 중간 프레임을 추가한다. 다시 모션을 지우거나 잘라 흔드는 식으로 해결하지 않는다.
3. `check-sprite.cjs`는 v13의 '정지 전신 1장만 사용'을 검사하던 테스트라 **현재 새 구현에 맞지 않는다**. walkingImage/walkingLoaded/WalkingAtlas mock과 포즈 교대 검증을 추가해야 한다. 단순히 기존 테스트가 통과했다고 새 걷기가 자연스럽다고 주장하지 않는다.
4. 기존 충돌·모바일·조직 마이그레이션 검사 후 배포한다.

새 걷기 작업은 이미지 생성·직접 아틀라스 확인·메타데이터 생성·렌더러 연결·JS 문법 확인까지 진행했다. **게임 화면에서의 새 모션 재생 검증, 회귀 검사 전체, 커밋/푸시/배포는 아직 완료되지 않았다.**

## 배포·인증

기존 Sites 프로젝트 ID는 `.openai/hosting.json`에 있다. 같은 서비스를 유지하려면 이 프로젝트를 이어서 수정해야 한다. 새 프로젝트를 임의로 만들 필요는 없다.

클로드 환경에 Sites 도구가 연결되어 있는지는 별도 확인해야 한다. 도구가 없다면 우선 로컬에서 수정·검증하고, 가능한 호스팅 경로를 사용자와 정한다. 기존 주소에 배포할 수 없는데 배포했다고 말하지 않는다.

인증 토큰, Git 쓰기 자격, 세션 쿠키, 환경변수 비밀값은 ZIP에 넣지 않았다. 기존 토큰을 코드에 붙여 넣지 않는다. 배포 시 해당 서비스에서 새로 인증한다. 현재 공개 사이트는 누구나 접속 가능한 상태다.

### 걷기 모션
- **4박자 전신 걷기**: 걸음 A(걷기 아틀라스) → 선 자세(기존 정지 전신) → 걸음 B → 선 자세. 모든 박자는 완전한 전신 이미지 한 장을 `drawImage` 한 번으로 그린다. 자르기·띠 변형·다리 흔들기 없음.
- `analyze-walk.py` 재작성: 기존 코드는 가로·세로 배율을 따로 적용해 걷기 프레임이 4~8% 옆으로 늘어났다. 이제 캐릭터·방향마다 **균일 배율 하나**(정지 머리 폭과 키의 기하평균)를 두 포즈에 공통 적용하고, 발바닥은 정지 이미지의 바닥선에, 머리 중심은 정지 머리 중심선에 맞춘다. 이미지 픽셀은 바꾸지 않는다.
- 시작·정지: 140ms 이상 멈췄다가 다시 움직이면 걸음 A부터 시작한다. 방향 전환과 짧은 멈춤에서는 주기가 이어진다. 정지하면 선 자세로 돌아가며, 이 자세는 주기 안의 중간 프레임과 같다.
- 방향: 플레이어는 입력 방향이 아니라 실제 이동 방향을 바라본다. 벽에 붙어 미끄러질 때도 마찬가지이고, 정확한 대각선에서는 현재 방향을 유지한다. NPC는 경로 첫·끝의 18px 미만 타일 중앙 보정 구간에서 방향을 바꾸지 않는다. 실제 3개 층 기준 방향 전환이 135회에서 35회로 줄었고, 150ms 미만 깜빡임은 6회에서 0회가 되었다.
- 접근성: `prefers-reduced-motion` 환경에서는 기존처럼 정지 이미지만 사용한다.

### 검증
- 실제 Chromium 화면에서 확인: 플레이어 4방향 걷기·정지·방향 전환, NPC 자리 이탈·배회·자리 복귀·착석, 모바일(iPhone 13 에뮬레이션) 방향 패드 걷기와 손 떼기.
- v13에서 만든 저장 데이터를 새 버전으로 열어 확인: 커리어 저장 그대로, 조직 ID와 컬렉션 동일. 변경은 `updatedAt` 하나이며, v13끼리 다시 열어도 같은 변경이 생긴다.
- `check-sprite.cjs` 재작성: 48셀이 시트를 빈틈없이 덮는지, 균일 배율, 6종×4방향 A→선 자세→B→선 자세 순환, 박자마다 drawImage 1회, 정지·착석·reduced-motion·로딩 전 대체, 대각선 방향, 실제 office-life.js로 NPC 시작 박자와 방향 깜빡임 0회를 검사한다. 이전 코드에 돌리면 실패해서 회귀를 잡는 것을 확인했다.
- 전체 검사(company, npc-floors, life, touch, office, sprite)와 dist/*.js 문법 확인 통과.
