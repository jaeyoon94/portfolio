Workflow

실행한 뒤, 결과를 확인하는 순서

  1. PM이 처리 기준 정의

    동기화할 데이터와 WBS·공정률 정리 기준을 정했습니다.

  2. BAT / Python 실행

    자료에는 Jira→Notion의 run.bat, WBS·공정률의 run.bat / .py 실행 형태가 기록되어 있습니다.

  3. 반영된 관리 정보 확인

    Notion 일감 DB와 Google Sheets의 WBS·공정률 정보를 확인하고 일정·일감 판단에 활용했습니다.

AI는 구현과 수정을 보조했습니다. 자동화가 만든 정보는 PM의 검토를 거쳐 판단에 사용했습니다.

초기 구현

실제 데이터에서 확인

동일한 TextKey가 여러 위치에 존재했습니다. 같은 Key가 있는 데이터를 모두 처리해야 했습니다.

요구사항 변경

중복 Key를 허용하고 모든 일치 데이터를 처리하도록 로직을 수정했습니다.

ChatGPT로 처리 로직과 구현 방향을 정리하고, Claude Code로 구현·수정했습니다. PM은 실제 업무 데이터를 적용해 예외를 찾고 다음 요구사항을 정했습니다.

Validation Evidence

검증에서 다음 요구사항으로

아래는 실제 포트폴리오에 기록된 구현·검증·수정 과정입니다. 실행 화면이나 코드 캡처가 아닌, 당시 업무 과정을 정리한 문서입니다.

소스·GUI·패키징 확인 범위

현재 저장소에서는 ProjectDME_클로드의 소스·README·config.json·Git 이력과 Excel Copy Tool의 Python 소스·GUI·패키징 파일을 확인하지 못했습니다.

GUI와 실행 파일 배포, 인증·경로 설정, Commit 절차는 검증된 구현 단계로 표시하지 않았습니다. 실제 소스와 실행 자료 확인 후 보완할 항목입니다.

자동화 이후의 판단

실제 데이터가 처리 규칙을 바꿨습니다.

첫 구현은 동작했지만, 중복 Key가 있는 업무 데이터에는 처리 규칙이 더 필요했습니다. 자동화할 범위를 정하는 것만큼 결과를 확인하고 예외를 요구사항에 반영하는 일이 중요했습니다. AI로 구현한 도구도 이 검토를 거친 뒤 업무에 연결했습니다.
