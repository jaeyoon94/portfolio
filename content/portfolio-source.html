일반 프로세스 예시 · 실제 프로젝트의 의사결정 규칙은 자료에 없습니다.

  1. 결함 접수대상 빌드·재현 조건·영향 확인
  2. 개발·QA와 영향 검토진행 불가·서비스 영향·검증 소요 확인
    • 배포 차단 필요 → 보류·수정 범위 협의
    • 영향 제한적 → 포함·제외·후속 수정안 협의
  3. 수정·재빌드가 필요하면개발팀 수정·재빌드 → QA 재검증
    PM은 담당자·전달일·배포 영향 조율
  4. 검증 결과로 다시 판단미해결이면 재검토, 충족하면 릴리즈 준비
    배포 여부는 조직의 승인 절차에 따라 결정

릴리즈 준비 체크리스트

일반 점검 항목 예시 · 실제 릴리즈의 완료 상태를 표시한 목록이 아닙니다.

  • 일정·반영 범위대상 기능·제외 항목·마감 변경 공유
  • 빌드 정보대상 버전·변경 목록·알려진 이슈 확인
  • QA 검증 결과차단 결함·잔여 이슈·재검증 여부 확인
  • 점검·공지 준비점검 시나리오·공지 담당자·준비 상태 확인
  • 배포 판단·비상 대응승인 담당자·연락 체계·복구 방안 확인
  • 업데이트 이후모니터링 담당·라이브 이슈 후속 일정 공유

배포 실행·기술 복구는 개발 담당 조직이 수행하며, PM의 단독 배포 승인이나 롤백 수행 경험을 의미하지 않습니다.

굿즈

방문 기념품

이슈 상태에 따른 워크플로우를 세분화하고, 담당자 할당 단계를 4단계로 나눴습니다.

  1. 상태별 흐름 검토이슈 상태에 따른 워크플로우 개선
  2. 워크플로우 세분화담당자 할당 단계를 4단계로 구분
  3. 단계별 담당자 지정각 처리 단계에 담당자 연결
  4. 개발실 공유변경한 처리 흐름 전달

담당자 지정부터 작업 처리, QA의 수정 확인과 빌드 확인까지 이어지는 절차입니다.
