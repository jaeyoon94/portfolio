# 페이지 폴리싱

대상: $ARGUMENTS

인자에 페이지가 없으면 어떤 페이지를 할지 먼저 묻는다. 인자에 "확인"이 있으면 4단계에서 멈추고 승인을 받는다. 없으면 끝까지 진행해 완성본을 가져온다.

## 여러 페이지일 때

- "사례 페이지 전부"는 projects.html의 프로젝트 사례 상세 페이지(tales-runner, project-dme, undecember, project-neon, goddess-order, legend-of-slime, the-k, vdi)를 뜻한다.
- 이미 폴리싱한 페이지(파일 머리에 `page-base.css`나 페이지 전용 CSS가 연결된 페이지)는 인자로 직접 지정하지 않는 한 건너뛴다.
- 스킬 불러오기와 레퍼런스 조사는 처음에 한 번만 하고, 페이지 종류(허브 페이지, 사례 페이지)별로 방향을 한 번씩 정한다.
- 색·글꼴·버튼·간격 같은 공통 규칙은 `page-base.css`를 쓰고, 페이지 종류에 공통인 규칙은 종류별 CSS 하나(예: `case.css`)에 둔다. 페이지마다 같은 토큰을 복사하지 않는다.
- 페이지를 하나씩 만들고 점검한 뒤 다음으로 넘어간다. 보고와 커밋 확인은 마지막에 한 번만 한다.

## 진행 순서

1. **현재 상태 보기.** 대상 HTML과 그 페이지가 쓰는 CSS·JS를 읽는다. 로컬 서버(`.claude/launch.json`의 `site`, 없으면 만든다)로 페이지를 열어 1440 화면을 직접 본다. `file://`로 열면 CSS·JS가 붙지 않으니 쓰지 않는다.
2. **스킬을 정식으로 불러 쓰기.** Skill 도구로 불러온다. 파일만 읽고 흉내 내지 않는다.
   - `unslop`: 진단 기준, 9단계, 마지막 체크리스트.
   - `design-taste-frontend`: 카피 규칙, 앱 창(app-frame) 원칙, 포인트 색은 한 번만.
   - `ui-ux-pro-max`: 검색 스크립트로 product·style·chart 도메인을 조회한다. 결과가 엉뚱하면 한 번 좁혀 다시 찾고, 그래도 안 맞으면 쓰지 않았다고 밝힌다.
   - `frontend-design`: 흔한 AI 디자인 패턴을 피하는 기준.
   - 그래프·수치가 있으면 `dataviz`: 형태를 고르고, 쓰는 색을 `validate_palette.js`로 실제 페이지 배경에 대고 검증한다.
3. **레퍼런스 조사.** 서브에이전트(general-purpose, 백그라운드)에게 비슷한 실제 서비스와 디자인 글을 찾게 한다. 이름과 URL, 구체적인 패턴, 사람이 만든 것처럼 읽히는 이유, 15줄 이내 추천을 받는다. 그동안 다른 단계를 진행한다.
4. **방향 정하기.** unslop의 5줄(목적·성격·세계·포인트·시그니처)과 화면 배치 계획을 쓴다. "확인" 모드면 여기서 보여 주고 멈춘다.
5. **만들기.** 이 페이지 파일과 이 페이지 전용 CSS·JS만 고친다. 공통 CSS(`style.css`, `site.css`, `cinematic.css` 등) 끝에 덮어쓰기를 쌓지 않는다. 헤더·푸터·내비는 다른 페이지와 같게 둔다.
6. **스스로 점검하고 고치기.** 1440·820·375에서 스크린샷을 보고, 기능을 직접 눌러 본다(탭, 필터, 입력, 업로드 등). 가로 스크롤과 콘솔 에러도 확인한다. unslop 체크리스트와 dataviz 안티패턴에 걸리는 것은 고친 뒤 다시 본다. 확인이 끝나면 뷰포트를 데스크톱으로 되돌린다.
7. **보고.** 쓴 스킬과 각각 어디에 썼는지, 참고한 레퍼런스, 바뀐 구성, 확인한 것과 못 한 것, 다른 페이지와 달라진 점(폰트 등)을 쓴다.

## 지켜야 할 것

- 사이트에 있는 사실·경력·기간·수치는 바꾸지 않는다. 새 성과나 주장을 만들지 않는다. 사례 설명은 다른 페이지에 이미 있는 문장에 근거한다.
- 가상 데이터는 가상이라고 한 줄로 분명히 표시한다. 그럴듯한 작업명·역할은 써도 되지만 실존 인물 이름은 쓰지 않는다.
- 피할 것: 그라데이션, 빛 번짐, 이모지 아이콘, 대문자 영어 라벨, 제목 끝 마침표, 의미 없는 반복 애니메이션, 링크 끝 장식 화살표, 순서가 아닌 목록의 01·02 번호.
- 커밋·푸시는 사용자가 확인한 뒤에만 한다. 원본 PDF·PPTX 같은 추적되지 않는 문서는 커밋에 넣지 않는다.
